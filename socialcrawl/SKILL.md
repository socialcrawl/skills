# SocialCrawl API

One API key and one response envelope for social, commerce, and research data. Lists are `{ items, next_cursor?, total? }`; add `?format=raw` to skip the transform pipeline. Every file below lives in `references/`; open only the one the task needs.

## API Key

Resolve the API key only when a live API call is needed. Documentation, capability, pricing, and code-generation questions do not need a key.

Check these sources in order without displaying their contents:

1. **Environment variable:** use `SOCIALCRAWL_API_KEY` when it starts with `sc_` and is not an example placeholder.
2. **Config file:** if the environment variable is absent, load `~/.config/socialcrawl/api_key` into `SOCIALCRAWL_API_KEY` in the current process. On POSIX shells, use `SOCIALCRAWL_API_KEY="$(<"$HOME/.config/socialcrawl/api_key")"; export SOCIALCRAWL_API_KEY`. On PowerShell, use `$env:SOCIALCRAWL_API_KEY = (Get-Content -LiteralPath "$HOME/.config/socialcrawl/api_key" -Raw).Trim()`.
3. **Missing key:** tell the user to create or rotate a key at https://socialcrawl.dev/dashboard and configure it as `SOCIALCRAWL_API_KEY` or in `~/.config/socialcrawl/api_key`. Do not ask them to paste a secret into chat. Stop before the live call until they say it is configured.

Never print, paste, log, or return the key. Never place a literal key in generated code, a command, a URL, an error message, or a saved transcript. Keep `$SOCIALCRAWL_API_KEY` (POSIX) or `$env:SOCIALCRAWL_API_KEY` (PowerShell) as a variable reference in examples. If the key appeared in chat or output, advise the user to revoke it in the dashboard and create a replacement.

## Workflow

1. **Find the call first (free, 0 credits, runs nothing).** `GET /v1/utility/find?task=<the job in plain words>` ranks the endpoints for the job, each with `method`, `path`, `params_filled` (taken from your words), `missing` and `estimated_credits`. Call `results[0]` directly when `uncertain` is false: its method, path and params are the ready call (add any `missing` param, then apply the Cost rule). When `uncertain` is true, show the options. For a job that needs several calls (a profile, then posts, then comments; a brand watch), `GET /v1/utility/plan?query=<the job>` returns the calls in order with params, price, and which step feeds which. Write or billing requests return no results. `find` and `plan` share a limit of 30 calls a minute and 1,000 a day per key; past it they still answer 200 but with `uncertain: true` keyword guesses, so in a loop over many tasks route from the bundled files.
2. **Fall back to the bundled files** when offline, when `find` or `plan` answers 404 (an older server: fall back to the existing flow), or when `uncertain` is true. Route with [Common jobs](#common-jobs) below, or grep [references/index.md](references/index.md): its Job to recipe table, then one line per endpoint (`grep -i transcript references/index.md`). For a recipe, read only its section: `grep -n '^## ' references/recipes.md` gives the line numbers; do not open the whole file. For an endpoint, read the platform file's TOC (from the top until the first `## `), then only its section: `grep -nE '^## (GET|POST|PUT|PATCH|DELETE) /v1/<platform>/<resource> - ' references/<platform>.md`, and read from that line to the next `## `. The section carries the exact cost, cache TTL, pagination, every parameter, the response fields, and the constraints checked before billing.
3. **Estimate.** Build the exact request and apply the cost gate below (one line for a small flat call, the full preflight in [references/cost-gate.md](references/cost-gate.md) for anything metered or large). A heading's number can be a per-row or per-page unit, not the request total.
4. **Call.** Resolve the key, then run the request exactly as the section shows it, keeping its HTTP method and body shape. If the user already asked to run this exact paid request, the cost disclosure is enough, except the Ask level: always ask (see the gate in the Cost rule); otherwise ask only before a paid call or wider scope they did not authorise.
5. **Report.** Return the data, then `credits_used` and `credits_remaining`. For an async job report the hold at submission and the settled charge on completion.

## Helpers

Bundled scripts in `scripts/` (Python 3). They read the key from `SOCIALCRAWL_API_KEY` or `~/.config/socialcrawl/api_key` and never print it; `--help` on each gives the rest.

```bash
python3 scripts/sc.py tiktok/profile handle=nike          # one call; JSON to stdout, credits_used to stderr
python3 scripts/paginate.py tiktok/post/comments --items 500 --max-credits 20 url=<post_url> > rows.jsonl   # page to N rows within a budget
python3 scripts/to_csv.py --archetype Comment --in rows.jsonl --out comments.csv   # rows to CSV with stable columns
python3 scripts/batch.py --urls links.txt > stats.jsonl   # stats for a file of post URLs (prism/post-stats, or one prism/jobs job past 500)
python3 scripts/estimate.py tiktok/post/comments --items 500 --offline url=<post_url>   # quote offline from assets/endpoints.json
```

**Code requests:** read the section and cost-gate, write a snippet that reads `SOCIALCRAWL_API_KEY` from the environment with a comment stating the billing unit, and present it without running it.

**Capability and pricing questions:** answer from the index and [references/pricing.md](references/pricing.md) (cost, tiers, packs, refunds, the free-endpoint list). Auth, envelope, pagination, labels, caching, idempotency: [references/api-overview.md](references/api-overview.md). The free `/v1/utility/*` calls answer from the live registry: `endpoints` (filter `?platform=`, `?search=`), `endpoint?id=tiktok/profile` (one endpoint, with measured field fill rates and production latency), `explain-error` (paste a failed response, get the fix), `plan?query=`, `resolve?input=<url or @handle>` (platform and every endpoint that takes it), `capabilities` (cross-cutting params and where each works), `docs-search?query=`, `recipes`, `quickstart`. `utility/ai-detection` is the one paid utility (1 credit a text).

## Making calls

Base URL `https://www.socialcrawl.dev`. Most endpoints are GET with query parameters (URL-encode values):

```
curl -s -H "x-api-key: $SOCIALCRAWL_API_KEY" \
  "https://www.socialcrawl.dev/v1/{platform}/{resource}?{param}={value}"
```

**Never assume the method.** Each endpoint section is headed by its real verb with a runnable curl. Batch reads, Prism jobs, web jobs, monitors, and cohorts use POST, PATCH, PUT, or DELETE with `content-type: application/json` (`web/parse` is multipart); the list, plus streaming (`Accept: text/event-stream`) and two-step endpoints that need an id from an earlier call, is in [api-overview.md](references/api-overview.md#non-get-routes-streaming-and-two-step-endpoints). Rate limits: 600 requests per minute and 50 concurrent per key; both return 429 with `Retry-After` and are never billed. Many endpoints take 10-45 s (task-polled sources, social profiles on a slow day): use a 60 s client timeout, or the endpoint's `recommended_timeout_s` from `GET /v1/utility/endpoint?id=` (free). Never time out early and resend a different request: an aborted call still runs, is charged and is cached, so resend the **identical** request and it comes back from cache at 0 credits. `POST` to `web/agent`, `web/sessions`, `web/monitors`, `web/parse`, `monitors` and `trustpilot/reviews/history` ignores `Idempotency-Key`: never auto-retry those, or you create (and pay for) a second one.

## Reading a response

Details are in [api-overview.md](references/api-overview.md). Seven rules before the first call:

- **Placement.** `pagination` (`next_cursor`, `has_more`, `page_size`) and the optional `meta.hint` sit at the envelope root. `dropped`, `_warnings` and every page report (`labels`, `relevance`, `label_share`, `hydration`, `walk`, ...) sit inside `data`. Read `data._warnings`: a parameter applied under the endpoint's own name (`sort was applied as sort_by, this endpoint's name for it.`), an ignored one (`limit was ignored: this endpoint's page size is fixed. ...`) or a handle that resolved to a different account (`resolved_to_different_handle`) is reported there, not as an error.
- **Paging.** Send `pagination.next_cursor` back as `cursor` and stop on `has_more: false`, not on a short page or on `total`. A page with no rows and `has_more: true` is not the end, so call again with `next_cursor`. A page the source returned empty costs nothing. A zero-match list is `200` with `items: []` at 0 credits.
- **Get more in one call; do not loop.** Every list endpoint takes `max_items=N` (walk pages until N rows), `max_credits=N` (never spend past it) and `max_pages` (1-50). Each page is billed as one call, `data.walk.stopped` says why it ended (`end`, `max_items`, `max_credits`, `time_budget`, ...) and `pagination.next_cursor` resumes ([details](references/api-overview.md#get-more-in-one-call-max_items-max_credits-max_pages)).
- **Empty lists say why.** Every `items: []` carries `data.empty_reason` and a one-sentence `data.empty_reason_note`: `no_matches`, `end_of_list`, `nothing_new_since` (your `since` / `stop_at_id` poll found nothing new), `window_filtered`, `relevance_filtered`, `row_filtered`, `already_seen`, or `source_empty_unverified`, the only one worth a retry. Tell the user which it is instead of reporting "no data" ([codes](references/api-overview.md#empty-lists-empty_reason)).
- **Default judgments are free.** Comment, post, review and keyword-search rows carry labels (`computed.labels`) and search rows a relevance score (`computed.relevance`) at no extra cost; `judgments=off` returns the raw page. Opt-in presets (`label=spam|toxic|low_quality|quality|ai_style|ai_written|injection|mention|reports|incentivized`, `relevant_to=`) add **1 credit per started 25 freshly judged rows**, held as `ceil(row cap / 25)` and refunded to the rows actually judged. `relevance=filter` against the query itself is free.
- **Date windows.** `since` / `until` (`YYYY-MM-DD` or a timestamp) work on about 155 dated lists and on `search/everywhere`. On 25 newest-first lists (the creator feeds and some comment, review and search lists) sending `since` sets their recency sort and the page that reaches the date ends the walk (`pagination.stopped_at`); every other list filters each page, keeps its cursor and bills every page walked, so an empty page that still has `next_cursor` is normal: keep paging. `published_after`, `start_date`, `from_date`, `publish_time=this-week` and `max_age_days` are read as `since`; `published_before`, `end_date` and `to_date` as `until` ([date window](references/api-overview.md#date-window-since-until)). A date on a list whose rows carry none is a free 400 (`unsupported_date_filter`).
- **Spend controls.** Creator post lists also take `stop_at_id`, so a poll pays only for new pages. Keyword searches take `min_views`, `country` / `exclude_country`, `sort_rows=views`, `seen=<id>` (repeats refunded) on top of the walk (**each page billed**).
- **`meta.hint`** names one other call that does the job in fewer steps. Its message states the price when that call costs more; follow it only within what the user authorised.

`include=` hydration joins rows to a sibling endpoint and is charged **per row on top of the page**, so never quote the plain heading cost for a hydrated call; the ceilings are in [cost-gate.md](references/cost-gate.md#row-hydration-include) and the traps in [api-overview.md](references/api-overview.md#row-hydration-include).

## Cost rule

Cache hits, idempotent replays, every `/v1/utility/*` endpoint except `utility/ai-detection` (1 credit), and `/v1/credits/*` cost 0 credits. Failed calls are refunded, and a request rejected for bad params, a page past the last page, or a rate limit never deducts. Metered endpoints hold an upfront ceiling and refund down to the work done, so the response `credits_used` is the real charge. A band that starts at 0 can settle at 0 (its legs bill only when they return rows), and the top of a wide band is a cap, not the expected charge: `prism/discover` never spends past its `max_credits`. Quote the total for the exact request, not the endpoint's base or unit cost. Scale the gate to the call:

| Call | Gate |
| --- | --- |
| Flat price ≤ 5 credits, user asked for it | One line: `≈ N credits` |
| Metered, multi-page, batch, monitor/cohort, or > 25 credits | Full preflight via `estimate.py` / `utility/estimate` |
| Upfront hold (worst case) > 500 credits or over budget (the user's stated budget) | Ask before calling |

Anything in between, or unsure of the price or params: quote first with the free `GET /v1/utility/estimate?id=<platform/resource>&<params>`. Any reply except a 404 means a current server (a 5xx or network failure is no reply: retry the estimate): use its quote, and `dry_run=1` is then free on any endpoint (validates, fetches nothing). A 404 or `ENDPOINT_NOT_FOUND` means an older server: do **not** send `dry_run=1` (it bills a normal call there, except the labelled dry run an endpoint documents); quote with `scripts/estimate.py` (offline, `assets/endpoints.json`) or the section's **Pricing** line. At every level, report `credits_used` after.

**If the task needs a whole list, price the whole walk before the first page.** Paging to completion multiplies the page cost by the page count, and a heading only shows one page. `instagram/followers` and `instagram/following` are the common case: about 50 accounts a page. A plain walk (5 credits a page) usually ends within a few rows of the profile's count (large verified accounts stop at about 50 rows on every route); `coverage=full` (10 credits a page) is only for a walk that fell short of `data.total`, and at that rate a 2,600-account list is roughly 520 credits, half that on a plain walk. Quote the total and get agreement before starting ([Multi-page walks](references/cost-gate.md#multi-page-walks-coveragefull)).

Errors: classify before retrying with [references/errors.md](references/errors.md), or paste the status and body into the free `GET /v1/utility/explain-error` for the fix. Never retry a 402 unchanged. Credits and balance: `GET /v1/credits/balance` (0 credits); the ledger is `GET /v1/credits/transactions?limit=50`; spend per API key per UTC day (up to 92 days) is `GET /v1/credits/usage?from=&to=&group_by=api_key,day` (both 0 credits).
